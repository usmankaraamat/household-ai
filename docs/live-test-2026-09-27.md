# Live test, 27 Sep 2026

The first run of this version inside real n8n (2.40.7), against real Notion, Google
Calendar and Fathom accounts, on the PC from [bench/README.md](../bench/README.md) (RTX 3060
Ti, 8 GB, Windows, Ollama 0.34.4). Then the first run of document search on a real personal
document set. Personal values are left out of this page; only what happened and how long it
took are here.

## Workflows in n8n

| Test | Result |
|---|---|
| Sample meeting → summary → approval → Notion | ✅ Worked, after the database got its **Meeting ID** column |
| Real Fathom meeting → poller → summary → approval → Notion | ✅ ID, card and phone numbers in the recording never left the machine |
| Same meeting approved twice | ✅ One page, one calendar draft. Google's 409 "already exists" was treated as done |
| Failure → activity log → **Retry**, then **From failed node** | ✅ Recovered cleanly |
| Restart while a run waits for approval | ✅ The approval survived a reboot |
| Hourly health check | ✅ Green on first run |

Model timings inside n8n, Granite 4.2 8B at an 8K context: 4–28 s per meeting summary,
depending on what else was loaded on the GPU.

## What the live run found, and what changed

1. **A failure log that said nothing useful.** For any rejected API call, n8n reports
   "Bad request - please check your parameters". Notion's actual reason ("Could not find
   property with name or id: Meeting ID") was only in Docker's logs. The error handler now
   logs the service's own reason as `detail`.
2. **The local model can't do date arithmetic.** "Dinner tomorrow at 7" landed on the meeting
   day with an end time equal to its start; "end of next week" became the next day. Decisions
   and action items often came back empty. The model now only reports the words said for the
   day ("tomorrow", "Saturday, October 10", "after three days"), and code turns them into a
   date. A missing end time means one hour, vague deadlines stay empty, and the approval form
   shows the words the date came from.
3. **Retries after a reboot were too short.** Approving right after a restart failed with
   ENOTFOUND: n8n was up before Wi-Fi, and three retries 5 s apart were over in 10 s. The
   workflow now waits for Notion and Google to resolve, up to about 3 minutes.
4. **A connection can quietly lose access.** The Notion database lost its connection to the
   integration, and nobody knew until an approval failed. A fourth workflow now checks
   Notion and Google Calendar every hour, and logs each service's own reason when one fails.
   It also catches Google's 7-day sign-in expiry for apps in testing mode.
5. **Account wiring took most of the person's time**, not the build: the Notion column first
   added as a row, a credential created but not selected on its node, a test user missing
   from the Google app. Budget for this with a client, since they own those accounts.
6. **Running the poller by hand makes it send a meeting twice.** n8n doesn't keep a manual
   run's memory, so the next scheduled check sends the meeting again. It's harmless thanks to
   the meeting ID, and the runbook now says not to.

## Document search on real files

29 files in nested folders: CVs as PDF and Word, transcripts, notes, ID card scans and
photos, a degree photo, and CV images.

| Step | Time |
|---|---|
| Text PDFs, Word and Markdown | 0.0–0.2 s each |
| Photo of a card, one read | 7–8 s |
| Photo of a card, with the structured second read | 13–17 s |
| CV image | 14–22 s |
| Back of an ID card (Urdu address only) | Loops every time: 78 s and 733 repeated lines at first; about 50 s once capped |
| All 29 files, final version | about 3–4½ minutes; the vision model is nearly all of it |
| Search index over the result | about 8 s |
| A question | 3–22 s |

Vision model: `qwen3-vl:8b-instruct-q4_K_M` (6.1 GB), the instruct build, so it doesn't spend
its output on reasoning.

What this run found:

1. **The converter only looked at the top-level folder**, and would have found nothing in a
   real, nested set of folders. It now walks subfolders. Names carry the folder path, and
   files that would share a name get their type and then a number added.
2. **Scanned PDFs need Pillow** (`pip install "pypdf[image]"`), and one file that fails no
   longer stops the rest.
3. **An image pulled out of a scanned PDF was rejected by Ollama** (400). Every image is now
   sent as an RGB PNG, at most 1600 px on its longest side.
4. **A small vision model can loop.** The Urdu-only side of an ID card came back as one line
   repeated 733 times. Output is now capped, and loops are collapsed with a visible note that
   flags the file to be checked against the original. A repetition penalty was deliberately
   not used: ID numbers repeat digits, and penalising repeats could cause misreads.
5. **Card layouts confuse later answers.** "Date of Issue" and "Date of Expiry" are printed
   side by side with both dates below, so a question about the expiry was answered NOT FOUND.
   Asking in words for "Label: value" lines didn't change the model's output. Structured
   output did: short documents get a second read as a JSON list of label and value pairs,
   and it paired the dates correctly, checked against the plain read.
6. **Citations flagged as invented were real.** The model shortens long file names
   ("degree.md") or swaps `_` and `-`. A citation now counts when it matches exactly one
   returned file.
7. **Still open: search misses when the wording differs.** "When does my CNIC expire?" doesn't
   reach the card, which the embedding search ranks below long notes that mention the same
   words. "What is the Date of Expiry on my National Identity Card?" finds it and answers
   correctly. Next step: hybrid search, which adds a keyword score to the meaning score.
8. **Still open: Urdu script.** This vision model doesn't transcribe it. It needs either a
   model that reads Urdu or a marker saying "Urdu text, not transcribed".
