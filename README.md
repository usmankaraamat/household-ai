# household-ai

A private home AI setup for a busy family. A computer at home runs local models over
sensitive documents, cloud services are used only where they clearly win, n8n moves data
between them, and a plain-language runbook means nobody is ever stuck.

This is a working first slice, built against one real brief using **made-up household
documents**. Every name, number and company in `data/` is invented.

## What works today

- **Meeting notes.** A transcript is summarized on the home computer. An outbound check
  removes IDs, account and card numbers and dates of birth, and a person approves exactly
  what will be sent. Then a Notion page and a *private, tentative, guest-free* Google
  Calendar draft are created. Both writes are keyed on a meeting ID, so a retry never makes
  a duplicate. Every step is logged, over-long input is refused with a clear message, and
  failures go to an error workflow.
- **Meetings from Fathom.** Every 10 minutes the home machine asks Fathom for new meetings
  and hands each one to the meeting workflow. Nothing on the internet connects in: Fathom
  can't reach the home machine, so the home machine reaches out.
- **Private document search.** You ask questions of the family's documents, answered by a
  local model with the source named, or `NOT FOUND` if the documents don't say. Your own
  PDFs, Word files and scans can be converted to text and searched too, in a `personal/`
  folder that git ignores; scans are read by a vision model on the same machine.
- **Measured limits of the local models.** Two models tested for accuracy (21 questions) and
  usable context (4K–32K). See [bench/README.md](bench/README.md).
- **Tests.** 41 tests run on every push without a model or an account: the benchmark
  scoring rules, document conversion, and each n8n Code node's logic under Node with its
  inputs mocked. [docs/test-plan.md](docs/test-plan.md) is the end-to-end check with real
  accounts.

**Tested end to end** (in n8n, against real Notion and Google accounts) on 26 Sep: the
first version of the meeting workflow. The version here adds the outbound check, the
meeting ID, the Notion look-up loop and the Fathom poller, and has not yet had that live
run.

## Headline results (RTX 3060 Ti, 8 GB)

| | Granite 4.2 8B | Qwen3.5 9B |
|---|---|---|
| Correct answers, out of 21 | 20 | 19 |
| Answers combining two documents | 3/4 | 2/4 |
| Output speed with 32K of context | 1.7 tok/s | 16 tok/s |

On 21 questions the two are close; the bigger difference is that Qwen stays usable on long
transcripts and Granite doesn't, on 8 GB. Speeds won't carry over to a Mac mini, so the
suite is built to re-run there.

## Run it

Needs Python 3.12, [Ollama](https://ollama.com) and Docker. The Python code uses only the
standard library.

    ollama pull granite4.2:8b
    ollama pull nomic-embed-text
    python -m search.index                       # build the local search index
    python -m search.ask "When is Leo's next flu shot due?"
    python -m bench.run                          # accuracy benchmark
    python -m bench.context                      # usable-context benchmark

    python -m unittest discover -s tests         # no model or account needed

    cp .env.example .env                         # then set N8N_ENCRYPTION_KEY and N8N_VERSION
    docker compose up -d                         # n8n at http://localhost:5678, local only
    python workflows/build.py                    # regenerate the workflow JSON

Import the three `workflows/*.json` files into n8n, add Notion and Google Calendar credentials, and set the
database and calendar IDs in the workflow's **Config** node. The Notion database needs a
**Text** property named **Meeting ID**. Then send the sample meeting:

    curl -X POST http://localhost:5678/webhook/meeting-transcript \
      -H "Content-Type: application/json" \
      --data @data/sample-transcripts/family-sync-2026-09-20.json

## Layout

    data/sample-docs/        fabricated household documents
    data/sample-transcripts/ a fabricated family meeting
    search/                  indexing, retrieval and the model client
    bench/                   questions, models, benchmarks and results
    workflows/               n8n workflows (meeting notes, Fathom poller, errors), generated by build.py
    personal/                your own documents, converted text and index; gitignored, never published
    tests/                   scoring and workflow-logic tests; run in CI on every push
    docs/                    data boundary, runbook, dry-run log
    logs/                    household.jsonl activity log (not committed)
